# Field Notes

`snapstore` is easiest to review by starting with the fixture, not the prose.

The domain cases cover `WAL pressure`, `snapshot width`, `compaction risk`, and `read drift`. They sit beside the smaller starter fixture so the project has both a compact scoring check and a domain-flavored review check.

The model rewards signal and confidence, then pulls back for drag. In this fixture, `stress` shows where that pullback matters most.

The language-specific addition keeps the review model in a package class with direct assertions.
